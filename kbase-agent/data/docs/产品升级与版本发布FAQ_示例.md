# 产品升级与版本发布 FAQ

## 发布节奏

产品按月发布小版本、按季度发布大版本。小版本以缺陷修复与体验优化为主，大版本包含功能新增与架构调整。

## 灰度发布

新版本先在内部环境与少量客户环境灰度验证，观察期内的关键指标正常后再全量放开。客户可申请加入灰度名单，提前体验并获得专属支持。

## 升级窗口

常规升级安排在业务低峰时段执行，具备滚动升级能力的组件做到升级期间服务不中断；需要停机的升级会提前在控制台公告。

## 回滚

每次发布均保留上一版本的可回滚镜像与数据快照，回滚决策由发布负责人做出。数据库变更采用向前兼容的写法，确保回滚不丢数据。

## 兼容性

大版本可能调整接口行为，此类变更会通过接口变更公告提前通知，并在旧接口上保留过渡期。

## 通知渠道

版本通知与升级公告的推送方式见《产品交付与售后FAQ》。
